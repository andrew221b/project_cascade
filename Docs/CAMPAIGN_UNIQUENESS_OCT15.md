# Уникальность уровней — 15 октября 2026

Исторический отчёт о первой проверке целых уровней. Последующее уточнение пользователя требует уникальности **каждого отдельного этапа**; прежнее допущение повторных этапов больше не действует. Текущее изменение и результаты: [уникальность этапов и декор](STAGE_AND_SCENERY_UNIQUENESS_OCT15_RU.md).

## Решение до изменения контента

Запрос: исключить повторные полные уровни внутри «Фигур», «Слов» и «Микса».
Проверка выполняется по рабочим определениям всех трёх этапов после привязки опубликованных рецептов через `ContentImporter` и `PublishedTriadStore`, отдельно для каждого языка. В «Миксе» учитывается фактическое чередование основных и локализованных уровней из `CascadeGame.PreferredLevels`.

У прежней проверки был пробел: `TriadRecipe.Fingerprint` различал отражённые конструкции и служебные значения. Более строгая проверка игнорирует имена символов, подписи уроков, ID, хеши и неактивные параметры. Она сохраняет равенство повторяющихся символов и все действующие параметры досок, контактов, прочности, ветра и длинного обмена. Горизонтальное отражение каждого этапа и перестановка тех же трёх этапов не считаются новым уровнем.

Найдено 6 групп и 8 лишних вариантов во всех категориях: `C199`, `C209`, `C238`, `C284`, `C288`, `C293`, `C304`, `C309`. Ранние варианты остаются. Для этих восьми узлов нужно подобрать проверенные решателем альтернативы с тем же главным приёмом, без уменьшения минимального числа действий на любом этапе и с ограниченным увеличением общей сложности. Остальные 532 рецепта сохраняются.

ID узлов, порядок кампании, исходные определения, цены, правила переходов, схемы и пользовательские сохранения не меняются. Старые рецепты архивируются для проверки уже заработанного прогресса сервером. Новые рецепты и их манифест одновременно обновляются в источнике и игровых Resources существующим издателем, только после проверки всех локализаций. Новая проверка становится обязательной частью публикации рецептов.

Отдельный этап может встречаться в разных полных уровнях; такие случаи нужно явно перечислять в отчёте. Запрос относится к уникальности полного уровня, состоящего из трёх этапов. Автоматическая проверка не доказывает субъективную интересность и не заменяет ручную игру.

## Проверки

После замены проверены все доступные уровни:

| Категория | Уровней | Уникальных полных уровней |
| --- | ---: | ---: |
| Фигуры | 500 | 500 |
| Слова, отдельно EN / RU / UK | 534 на язык | 534 на язык |
| Микс, отдельно EN / RU / UK | 540 на язык | 540 на язык |

Повторов нет даже при независимом отражении каждого этапа и перестановке этапов внутри уровня. Общее число узлов кампании — 540; доступные наборы категорий различаются по существующей логике выбора. Проверка не складывает переводы одного уровня в ложные повторы.

Изменены только восемь запланированных рецептов. Минимумы `C199` и `C209`: `2 / 3 / 1 → 2 / 3 / 3`; у остальных шести сохранилось `3 / 4 / 5`. Главные приёмы сохранены: контакт с печатью и путь с закрытыми обменами. Все 532 остальных рецепта, исходный каталог, порядок и шесть файлов определений/слов/локализаций сохранены.

Проверки реального кода C#:

- 121 проверка нормализации, совпадения Resources и совместимости; из них 17 проверяют сам критерий уникальности.
- 6471 повтор выигрышных маршрутов основных и локализованных этапов.
- 1620 оптимальных сертификатов, 335 действующих бомб, 646 проверок необходимости полезных эффектов, 3294 пробы уменьшения прочности, 372 значимых входных преобразования и 12 порывов ветра. Нет лишних досок, перестановки атомарны и сохраняют набор символов.
- 32 старых сохранения посреди уровня, включая EN / RU / UK, восстановлены через настоящий `ProfileStore`; отмена хода работает. Прежние рецепты точно сохранены в серверном архиве.
- 124 проверки серверных границ прошли с имитацией транспорта SDK, включая старые заработанные результаты всех восьми заменённых узлов и отклонение поддельных доказательств.
- `publish_campaign_recipes.py --check` подтвердил совпадение опубликованных ресурсов и новый критерий уникальности. Основной Unity Editor импортировал обе изменённые TextAsset с прежними GUID.
- Основной Editor через официальный Unity MCP сверил все 9 фактических сочетаний категории/языка с проверенным списком и снял 24 кадра всех заменённых этапов в размере 390×844. Просмотрены три обзорных листа: изменённые доски, контакты, цели и управление помещаются в мобильный экран. Ошибок и предупреждений в итоговой Console нет; Play Mode остановлен, пользовательская несохранённая сцена не сохранялась и не закрывалась. Доказательства: `Reports/CampaignUniquenessMcpOct15/`. Первый неудачный запуск проверочного сценария (диалог перехода в другую категорию) сохранён отдельно; игровую блокировку диалога не меняли.

Машинные результаты: `Reports/CampaignUniquenessOct15/validation.json`, полный список и отпечатки — `levels.json`, оптимальные маршруты/механики — `progression.csv`, подробная проверка решателем — `solver-result.txt`. Исходный провал строгой проверки оставлен в `Before/`. Отдельные повторяющиеся этапы внутри разных полных уровней перечислены явно в `repeated_stages`; это не проверка уникальности каждого подэтапа по всей игре.

Повторяемый запуск: `python3 Tools/check_campaign_uniqueness.py`. Как и у издателя рецептов, при нестандартной установке Unity нужно задать `CASCADE_UNITY_EDITOR` до каталога `Unity.app/Contents`. Для проверки старых сохранений дополнительно передать `--previous Reports/CampaignUniquenessOct15/Before`.

Перед выпуском пересобрать и развернуть Cloud Code вместе с клиентом: модуль встраивает актуальные `Data/production_triad_recipes.json` и архив `production_triad_recipes_legacy_oct09.json`. Удалённый сервер в этой задаче не менялся. Новые ID или настройки стора не требуются.

Не выполнялись сборка/установка на физический телефон, профилирование устройства или развёртывание сервера. Снимки получены настоящей камерой Unity в мобильном разрешении. Сравнение структур не является полным доказательством изоморфности всех возможных игровых путей и не подтверждает субъективную интересность каждого уровня.
