## C05. Канонический resolver

```text
1. Validate по PRE-state.
2. Подготовить новый state и snapshot истории.
3. Выполнить полную атомарную перестановку либо установить ForceExit.
4. На окончательном ряду проверить контакты:
   BombDefuse → Key → Repair → OptionalStamp.
5. Ещё вооружённой бомбе снять ровно один такт; при нуле — взрыв.
6. rawHP = HPbefore − fullSwapCost + oneShotRepair − bombDamage.
7. Учесть расход одноразового моста и один принятый ход.
8. Если ForceExit или rawHP ≤ 0: покинуть этаж ровно один раз.
9. Вход на следующий: локальные начальные значения → один EntryTransform → контакты.
10. Если это приёмник: сравнить весь ряд с TargetSymbolIds.
11. Сохранить итог; отправить presentation events.
```

Операции ремонта в коде могут прибавлять к временной signed HP до шага 6; результат обязан быть алгебраически тем же. **Не обнулять отрицательную прочность посреди расчёта.**

Контрольный случай: `HP 1 − cost 2 + repair 1 = 0`, платформа разрушается. Вариант `max(0, 1−2)+1=1` неверен.

### Вход на этаж

Используется и при первом запуске уровня. Бомба на входе не теряет такт. Если после входного конвейера требуемый символ уже оказался над ней, она обезвреживается сразу. Ключ и ремонт тоже проверяются после преобразования.

BaseDurability положительна. На входе нет произвольного урона и бесконечной цепи пустых обрушений. Уровни с первым входным сдвигом требуют отдельного preview до управления; в начальном наборе верхний сдвиг не используется.

### События для визуала

`CommandAccepted → RowPermuted → ContactResolved → BombTick/Defused/Exploded → DurabilityResolved → FloorExited → FloorEntered → EntryPermuted → ReceiverEvaluated`.

Рендерер может пропустить анимацию и синхронизироваться с final-state. Он не снимает HP из OnComplete. `OnApplicationFocus` не вызывает EntryTransform повторно.
