# Account, first-launch reminders and store assets — 2026-10-09

Design note before implementation: extend the installed Unity Authentication / Unity Player Accounts browser flow, which supports Google and Apple; do not add another identity backend or native token SDK. Keep anonymous play and explicitly choose before replacing the current save with an existing account. Do not force-link identities or merge purchases across unrelated accounts. Cloud Code remains the authority for purchased entitlements and balances. Public Player Accounts client ID goes in Configs/authentication.json; no secrets in the game. Enabling cloud awaits real endpoint/provider setup and a live round trip.

Local reminders default off for new profiles. The OS permission request appears only after the player turns reminders on in Settings; persist the permission-request marker before the OS prompt, keep reminders off on denial, and never prompt automatically at startup. The app queues a two-week rolling schedule of morning/evening local reminders and refreshes it on return to the game; no APNs server registration is used.

A never-taught blocking branch must get an explanation even on a later stage of a three-stage level. Learned mechanics remain quiet; add a one-time revised branch-coach marker for older profiles incorrectly marked taught.

Artwork: English; five store images, first three illustrated with actual gameplay displayed in a phone, last two lifestyle with a visible genuine gameplay display. Screenshot sources must be physical iOS or iOS Simulator; editor images must not be labeled device captures. Apple store PNGs are opaque, in an accepted iPhone resolution; Google feature graphic is 1024×500 opaque and contains no device hardware. Prepare Apple layered icon source and Google 512×512 icon separately. Never claim rankings, live multiplayer, free purchases, or functioning unconfigured cloud. Existing art/meta stays intact; new icon is a sibling asset.

Account journal additive fields: AuthenticationProfile (legacy default) and AccountCandidateProfile persist SDK session namespaces, never credentials. Existing-account loading uses a separate SDK profile; declining can recover the original cached guest identity even after a failed remote load. Canonical player/cloud profile schema remains unchanged.

## Включение входа после заполнения конфига

1. В Unity Dashboard включить Authentication / Unity Player Accounts для проекта `a1b8a760-5a0c-4c2d-8ae7-54c1b411259a`. Полученный публичный Client ID вставить в `Configs/authentication.json` → `unityPlayerAccountsClientId`. При установленном Player Accounts вход Google/Apple выбирается в защищённом окне провайдера; отдельные нативные OAuth SDK не добавлялись.
2. Применить через Unity → `CASCADE / Release / Apply Apple and Google sign-in configuration`. Создаётся штатный Resources-asset Player Accounts, используемый SDK и его обработкой мобильных deep links. С пустым Client ID импорт отказывается менять настройки.
3. Для среды `production` развернуть существующий Cloud Code модуль `CascadeAccount`, настроить защищённый Cloud Save и сервер проверки чеков по `Docs/RELEASE_SETUP_OCT09.md`. Секреты проверки чеков остаются на сервере. `cloudCodeDeployedAndVerified` и `purchaseVerificationConfigured` включать только после реальной проверки соответствующих сервисов.
4. Проверить вход Apple и Google, отказ/отмену входа, перенос на другое устройство, загрузку уже существующего аккаунта и выбор сохранения этого телефона, восстановление подтверждённых покупок. Client ID сам по себе не включает облачную синхронизацию.
5. **Перед включением аккаунтов в релизе ещё нужен полный путь удаления игрового аккаунта и связанных данных.** Текущая кнопка Manage account ведёт в Unity Player Accounts; удаление там не удаляет данные игры в других UGS-сервисах. Нужны обработка удаления Cascade/Cloud Save, отзыв сессий и доступная пользователю страница удаления для Google Play. Этот серверный путь ещё не реализован/не проверен; нельзя считать его завершённым настройкой одного Client ID.
6. Заполнить privacy/support URLs и ответы Apple App Privacy / Google Data Safety по реально включённым Player Accounts, рекламе, покупкам и аналитике. Для реальной монетизации публичные ID лежат отдельно: `Configs/admob.json` (6 ID) и `Configs/release-ids.json` (store IDs/товары/серверные настройки).

По ответу пользователя конфиг оставлен пустым, обе production-активации выключены. Live-проверка входа/облака/покупок не выполнялась. Разрешения уведомлений проверены в чистых тестах на уровне политики/сохранения; настоящий OS prompt и доставка напоминания на телефоне ещё требуют проверки. Для рекламных снимков уведомления отключены только в отдельной QA-копии.
