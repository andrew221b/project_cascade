## C09. Математика, решатель и что именно он доказывает

### Базовая перестановка

Без устройств, с различными элементами, минимальное число соседних обменов равно числу инверсий относительно цели. Максимум:

```text
n(n−1)/2
n=4 → 6; n=5 → 10; n=6 → 15; n=7 → 21; n=8 → 28.
```

При повторениях число разных строк равно `n! / product(multiplicity!)`. Для цели с двумя одинаковыми треугольниками, тремя разными буквами и двумя кругами: `7!/(2!·2!)=1260` разных перестановок.

Для подсчёта инверсий с повторами используется стабильное сопоставление очередного одинакового символа с очередной целевой позицией. Это диагностическая оценка базовой сортировки. **Она не является нижней границей маршрута с бесплатным входным конвейером:** сдвиг может решить несколько инверсий за одну команду Drop. Не вставлять обычные инверсии в A* как доказанно допустимую эвристику для всех устройств.

### Почему поиск конечный

Потенциал состояния: положительная прочность текущего и нижних этажей плюс ещё не использованные ремонтные прибавки. Каждый Swap расходует минимум 1. Получение ремонта уменьшает запас неиспользованного ремонта на ту же величину. Drop отбрасывает положительную прочность текущего этажа. Мост, ключ и печать не производят ресурс бесконечно.

Поэтому accepted-путь имеет конечную длину; грубая верхняя граница — `sum(BaseHP + RepairAmount)` по этажам. Уменьшение графа не требует бесконечной физической симуляции.

### Resolver и solver — одни правила

Для одинаковой стоимости **команды** BFS на малых задачах даёт минимум. Хрупкий обмен стоит 2–3 прочности, но всё ещё одну команду: Dijkstra для этой метрики не нужен.

Ключ состояния включает ряд, этаж, HP, локальные статусы, bridge/repair/key, причины исходов бомб и печати. RouteLength/UUID визуальных объектов/список Undo в hash не входят.

Для обычной цели часть счётчиков можно оптимизационно исключить; для контрактов «обезвредить», «оставить», «взорвать» это запрещено. В reference-модели счётчики сохраняются и в обычном поиске ради простоты.

Runtime Hint получает один путь из текущего state. Полный граф создаётся при авторской проверке/внешнем runner; не считать все уровни в кадре на телефоне. При бюджете 200 000 состояний в reference результат превышения — `UNKNOWN`, не `UNSOLVABLE`.

### Метрики

| Метрика | Как считать | Чего не утверждает |
|---|---|---|
| OptimalActions | Расстояние от initial до подходящего Won | Не оценка удовольствия |
| NearOptimalFirstStates(+2) | Различимые состояния после первого хода с полным путём ≤minimum+2 | Не все варианты управления |
| ForcedRatio | Доля решений на оптимальном DAG с единственным следующим состоянием | Не автоматически «плохой уровень» |
| EarliestDeadDepth | Первый достижимый нетерминальный тупик | Не физическое падение |
| DeadStates | Нет пути к подходящей цели | Принимается только после завершённого поиска |
| RequiredMechanics | Сравнить маршруты и временно удалить механизм в authoring-тесте | Удаление может облегчить пазл; нужен просмотр идеи |
| VisualLoad | Ряд, число активных значков и преобразований | Отдельная UI-гипотеза |

Ошибка «не тот swap», затем обратный **игровой** swap стоят два действия. Один дополнительный HP не означает, что прощена одна ошибка. Бесплатный Undo — удобство интерфейса, а не запас прочности.
