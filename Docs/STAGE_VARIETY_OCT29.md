# Personalised stage vocabulary — implementation contract, 29 October 2026

The user requests new words / shape combinations on every stage, a different shuffled order per player, and real words plus shapes from the first Mixed round. Current rows support 3–8 symbols. Existing dictionaries have 40 EN,35 RU,36 UK entries, including only 5 three-letter words per language. `DescentRun` currently applies the source target to all three stages. Mixed alternates pure Shapes/Words for width 3, and uses one-letter pronouns for some repeated-symbol lessons; that does not meet this request.

The new vocabulary and draw sequence must be separate from the historical source catalog and its pinned content hashes. Keep old level IDs, receipts, rules and economy readable. Add a versioned run/proof path rather than weakening legacy replay verification. Every stage's chosen symbols and word segments are pinned in its content hash; the server reconstructs the same permitted target and recipe instead of trusting client-supplied words or boards. Completed-stage validation compares against that stage's own target.

Use an offline, versioned 3–8-letter pool for EN/RU/UK; preserve ё, і, ї, є, ґ and Unicode graphemes. Do not copy definitions. Record exact source provenance, notices and licences, filter names/abbreviations/profanity, and keep the data separate from code. A player-owned shuffled deck is shared across Words/Mixed draws for the same locale and length. Consume each eligible word before reshuffling; keep adjacent stages / rounds distinct at deck boundaries. Persist the seed and draw state so process restarts and cloud synchronisation do not restart a common public sequence.

Preserve the mathematical equality pattern when renaming an existing proven recipe. For the small set of short/repeated-symbol sources that cannot contain a real word of at least 3 letters plus a shape, author and solver-prove explicit canonical alternatives. Mixed width 3 must use at least 4 slots. Visible Shapes use the six actual existing meshes (A–F); aliases T/O must not create fake new combinations. Shape decks use ordered target combinations and exclude the previous stage. Never display duplicate-looking letters as different logical pieces just to reuse an old proof.

Audit all 540 nodes ×3 stages for every applicable mode/locale. Verify solver witnesses, contacts and minimum-action certificates, bounds/Unicode correctness, seed diversity, no repeats before pool exhaustion, exact server reconstruction, old receipts/checkpoints, and mobile rendering of early Mixed. No player build, installation, store upload or deployment is authorised by this code/content request; prepare compatible server sources and tests for the next coordinated release.

## Implemented

`StageWordPool` pins 46,572 spelling-dictionary entries:8,142 EN,16,534 RU and 21,896 UK. Bucket sizes for lengths 3–8 are 559/1540/1870/1839/1468/866 (EN),473/1249/2538/3382/4226/4666 (RU), and 500/1427/3089/4638/5686/6556 (UK). Entries are uppercase NFC, alphabetic and have distinct letters. Restricting to distinct letters lets ordinary words safely rename the existing all-distinct mechanical certificates; repeated-symbol lessons use explicitly certified alternatives. This is a spelling pool, including inflected and uncommon words, not a claim of native editorial review of every entry. Familiar curated words form the separately shuffled opening tier for each length, before the rest of the deck. External spelling flags, names/abbreviations and authored/CC-BY filtering exclude unsuitable entries. All allowed exceptions still must exist in the source dictionary.

`stage_words_v1.json` is immutable once released. The compiler records source/affix/filter hashes and refuses an accidental change to the frozen pool. Notices are in `Data/Licenses/StageWords`; the readable modified data, compiler and notices ship in `StreamingAssets/StageWordPoolSource.zip`. EN uses the SCOWL notices in README_en_US; the adjacent generic GPL en/license.txt does not describe this dictionary. RU uses its redistribution notice; UK data uses MPL 1.1. Source references and notices are included rather than importing another runtime dependency.

All 540 stable campaign nodes are offered in each category. The shared `StageVarietyMemory` owns one random seed and compact used-word bitmaps across Words and Mixed. Cloud reconciliation ORs the bitmaps even across different device seeds. A cold start discards unfinished boards as before, retaining vocabulary history. Each reserved run consumes three new words; retries consume another word for the retried stage. Unplayed reserved words may be skipped, never prematurely reused. A finite word bucket is reshuffled only after exhaustion; immediate boundary repeats are excluded. Full campaign traversal across Words and Mixed consumes no word twice. This does not promise an infinite supply of unique words during unlimited replay.

`StageContentBasis` uses the six real shape meshes. Shuffled permutations change between stages and rounds; retry selection excludes both neighbouring stages and the current combination, and preserves the last reserved stage as the next round's neighbour. Normal target equality patterns are preserved. Sixteen solver-certified alternative triads cover 3-slot Mixed→4 slots, repeated-letter sources→real Words/Mixed, and the 8-slot Shapes route. Mixed has a word of at least 3 letters and at least one shape on every stage, including C01.

`DescentRun` protocol 7 pins each stage's symbols, vocabulary version and mechanical recipe. Its stage hash is independent of unplayed future draws, so retrying stage 2 does not invalidate the completed stage 1 proof. The old source catalog hash and protocols 1–6 remain unchanged. `StageVarietyStore` reconstructs targets and permitted recipes on client and Cloud Code; uploaded word strings, boards or a claimed reward cannot replace published certificates. Custom personal missions use their existing independently proved boards and receive the same vocabulary draw path. Server grant rules are unchanged.

The frozen dictionaries and certificates parse on a background task; Unity resource access stays on the main thread. Per-player data is bounded and compact. No network dictionary lookup, runtime spelling service or new package is required. Temporary preparation respects the source's native glyph locale before mounting the selected language; this avoids a real RU/UK failure on long native-English source boards. The transient stage plaque wraps into its available field on compact screens without crossing icon controls.

## Validation and rollout

Final evidence is stored in `Reports/StageVarietyOct29/verification.json`, NUnit XML, actual Unity renders and `targets.json`. The pure-engine audit replays every witness and verifies shortest-path minimums for 540×3 stages×3 modes×3 locale sweeps (14,580 checks; Shapes is language-independent). It checks shared Words/Mixed history, actual visible shape identities and Mixed composition. Targeted Editor checks cover retry, mode switching, Unicode alphabets, compact 320×568 and 390×844 rendering, cold starts, custom missions, cloud merge and old checkpoints. Cloud Code tests reconstruct real new clears and reject changed pool, seed, commands, draw or target.

These are source/content changes. No mobile player was built, installed or uploaded and no live service was deployed for this task. Publish the compatible Cloud Code module before distributing a client that emits version 7 receipts; the module continues accepting the existing version 6 clients. Device/store release validation remains part of that separately authorised release.
