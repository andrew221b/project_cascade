# Brief native haptic feedback

`NativeHaptics.Pulse(float strength)` is a presentation-only device bridge. The caller owns player preferences, focus/pause checks and the request cooldown. Zero/negative or NaN strength does nothing; positive strength is clamped to 0–1. The Editor and desktop builds do nothing. Missing native entry points or Android Java failures produce one concise warning and disable further native requests for that session; missing vibration hardware simply does nothing.

- iOS 13+: UIKit light/medium impact feedback, with intensity capped at 0.65. Requests execute on the main thread and prepare the generator for the next nearby tap. iOS 10–12 uses a light impact; older systems do nothing. UIKit decides whether supported hardware and system settings permit feedback. See [Apple impact feedback](https://developer.apple.com/documentation/uikit/uiimpactfeedbackgenerator/impactoccurred(intensity:)) and [preparation timing](https://developer.apple.com/documentation/uikit/uifeedbackgenerator/prepare()).
- Android API 26+: one-shot pulses last 10–25 ms with amplitude 40–110 on motors that support intensity control. Other motors use a 10 ms default-amplitude pulse; lower Android versions use a 10 ms legacy pulse. The bridge checks vibrator availability and catches Java failures. Devices without intensity control cannot guarantee the same perceived strength. See [VibrationEffect](https://developer.android.com/reference/android/os/VibrationEffect#createOneShot(long,%20int)) and [Android haptic compatibility](https://developer.android.com/develop/ui/views/haptics/haptics-apis).

## Design note

The isolated `CascadeHaptics.androidlib/src/main/AndroidManifest.xml` adds `android.permission.VIBRATE`, required by the Android APIs. It declares no application, activity, SDK version, ad setting or runtime permission dialog. The Gradle namespace `com.cascade.haptics` identifies this new library; the existing application ID and ad libraries are preserved. Native source is included through Unity's [iOS plug-in mechanism](https://docs.unity3d.com/6000.0/Documentation/Manual/PluginsForIOS.html) and [Android library import](https://docs.unity3d.com/6000.0/Documentation/Manual/android-library-project-import.html). The modern `src/main` layout and minimal Gradle configuration follow [Unity's library creation guidance](https://docs.unity3d.com/6000.0/Documentation/Manual/android-library-plugin-create.html), inheriting existing project SDK settings. No SDK or package is added.

## Validation limits

The C# bridge compiled with Unity's bundled Roslyn compiler and actual Unity reference assemblies for Editor, iOS and Android preprocessor branches. The iOS Objective-C++ shim passed Clang syntax-only validation against the installed iPhoneOS 26.5 SDK with an arm64 iOS 13 target. The isolated permission manifest parsed successfully; new metadata has no trailing whitespace. Native iOS/Android builds and physical vibration were not run. Device acceptance still requires checking that selection is subtle, strong feedback remains brief, the haptics setting disables requests and rapid overlapping events do not buzz continuously. These source checks do not establish physical tap quality.
