## Atomic storage

Cloud Save does not provide SQL transactions or a safe synthetic write-lock for a missing key. Never invent a lock or use unlocked first writes to mutable account state. Bootstrap fixed private index shards administratively before activation. Publish immutable content-addressed snapshots; update an existing index shard with the real Cloud Save write lock. Competing first writes and account updates therefore have one CAS winner, stale writes cannot replace committed data, and failed attempts can leave only unreferenced immutable blobs. Use the same pre-existing-CAS discipline for immutable global purchase/transaction ownership. Bound records and retries; retain tombstones and purchase replay fingerprints.

No in-memory semaphore is a distributed lock. No shadow writing from both old and new authorities. Do not flip the active module until controlled concurrent-write, transaction ownership, reward replay, subscription and deletion tests pass and existing records compare exactly.

## Server hardening deployed — 28 October 2026

The production module now reports version `20261028.2`; raw storage routing is `Unity2`, normalized to `Unity` for existing clients. Only compatible directory readers may be deployed after activation. Do not revert the route to `Unity` or restore the previous directory implementation after branch publication. Recovery uses a compatible module artifact and existing CAS-protected references, never the purged SQL game database.

Private work indexes `fl_lane/fl_due` and `fl_owner` were created and verified READY before indexed writes. A reserved disposable live record proved compound/owner queries and atomic stale-batch rejection, and was removed. Snapshot publication uses a random per-attempt nonce and existing-parent CAS. Small directory leaves split into uniquely prepared generations; losing unpublished generations are eligible for cleanup. Indexed due-work processing replaces full player/shard sweeps. Current snapshots remain pinned; retired snapshots, expired deletion capabilities, unpublished children and pending deletions are independently retried with backoff. Per-job failures cannot stop unrelated owners. Metadata upgrades completed for all existing active shards without changing profile payloads or purchase ownership.

Only Unity Scheduler is enabled, as explicitly chosen by the owner. Sixteen lanes run once per hour at minutes 0,3,7,11,15,18,22,26,30,33,37,41,45,48,52,56 UTC; each event has a matching Cloud Code trigger. This is 11,520 scheduled invocations per 30 days, before retries and player requests. Empty jobs make bounded metadata requests and no publisher lookups. Maintenance freshness allows 90 minutes. Cleanup/recovery can therefore wait for the next hourly lane; purchase/reward confirmations, account synchronization and signed subscription notifications run immediately in their normal requests. No workers.dev address, Cloudflare cron, new paid plan or mobile player build was created.

Completed service tokens and encrypted publisher configuration are cached with expiry and credential/reference fingerprints. Failed/in-flight requests and mutable player state are not cached across workers. Account and authoritative effects load together. ReadReward checks confirmation before loading the returned wallet, eliminating an acknowledged receipt paired with an older balance. Requests have cancellation/deadline budgets, bounded parallelism and safe structured operation metrics. Publisher outages remain retryable. Apple transaction environment is an untrusted routing hint only; authenticated publisher fields, bundle, ownership and account binding still decide validity. Alternate-environment lookup is restricted to not-found responses.
