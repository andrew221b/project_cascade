# Guided lesson input — 8 October 2026

During first-use practice, only the action displayed by the hand is accepted.
The application input owner binds an exact command or control to the current
state. Unrelated selection, drag, keyboard moves, descent, undo, hint and tool
transactions are rejected before state or inventory changes. Pause/navigation
remain available; returning preserves unfinished practice. An ambient wind
lesson blocks player actions while allowing the actual gust to occur.

The same validated command drives the finger and the input restriction.
Multi-step contact lessons follow a bounded route to the teaching event and a
solvable continuation, using the existing resolver. An unavailable example is
deferred without marking it learned or holding an invisible input lock. A
successful action releases practice even if its persistence needs recovery.
No Domain transitions, economy, prices, IDs, save schemas or packages change.

Contact practice may be announced immediately before landing on the next
board; the verified route can prepare on the current/teaching board but cannot
leave the teaching board without the actual contact. Entry guidance uses the
proved command rather than forcing Drop when a preparatory swap is required.
Owner actions (tools, hint, undo, bag, checkpoint descent) have explicit gates.
Hint request and the subsequent finger-guided move are separate input phases.

Precision focus moves directly to the allowed pair rather than getting stuck
on blocked intervening slots. Its direction control can perform the indicated
far reach; ordinary moves retain their original adjacent-swap behavior.
